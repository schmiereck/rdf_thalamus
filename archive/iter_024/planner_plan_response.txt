    """

Now I have a thorough understanding of the complete codebase and state. Let me formulate my plan.

The key insight from iter_023 is:
1. SFA (slowness) works mechanically but does NOT produce identity encoding
2. Multi-step SFA is the last slowness-based shot
3. A contrastive contingency arm is mandated
4. A JEPA-readout stop-gradient diagnostic is cheap insurance

The fundamental problem is: **SFA just makes z_dyn uniformly slow, it doesn't create category structure.** A contrastive objective using temporal natural augmentations (same object across time = positive pair, different objects in same frame = negative pair) directly creates the category structure that SFA cannot.

Here's my plan design:

**Primary Arm (A): Multi-step SFA** — The last slowness shot. SFA computed over k={20,50,100} timesteps instead of k=1. Multi-step SFA accumulates gradient over longer horizons, potentially extracting slower features that survive longer temporal windows. Uses d_max=8, CGIR, CCR, d_t=3.

**Contingency Arm (B): Temporal Contrastive (TC)** — The non-slowness probe. NT-Xent loss on z_dyn where positives are the same object's z_dyn at different timesteps, and negatives are different objects' z_dyn at the same timestep. This uses the physics engine's object IDs (available from `info["colors"]`) as weak supervision for object matching across time. No color labels needed — just temporal coherence of the same physical object. Replaces SFA as primary objective; retains VICReg.

**Arm (C): d_max=16 with multi-step SFA** — Carries forward the best d_max from iter_023.

**Arm (D): JEPA-readout stop-gradient diagnostic** — Single seed, sim_weight=0 on the SFA arm. Tests whether removing the JEPA readout entirely changes the picture.

Let me think about the contrastive implementation more carefully. The NT-Xent approach:

For each frame, we have 3 objects. We can track objects across timesteps because the physics engine maintains consistent object indices (obj 0 at time t is the same physical object as obj 0 at time t+1). So:

- Positive pair: z_dyn for the same object (same channel) at two different timesteps
- Negative pair: z_dyn for different objects at the same timestep, OR same channel at different timesteps when the dim-to-obj mapping has changed

But wait — the current architecture doesn't have per-object z_dyn channels. The z_dyn is a d_max-dimensional vector where channels don't have a fixed object assignment. The dim_to_obj mapping is discovered post-hoc. So we can't directly apply per-object contrastive loss without either:

1. Using the dim_to_obj mapping at training time (circular — we'd need to discover it online)
2. Using a different formulation

The temporal augmentation contrastive approach is actually simpler and doesn't need object IDs:

**Temporal Contrastive (TC) formulation:**
- For each sample in the batch, we have z_dyn(t) from the current frame and z_dyn(t-k) from a previous frame
- **Positive pair:** z_dyn(t) and z_dyn(t-k) for the same sample (same physical scene across time)
- **Negative pair:** z_dyn(t) from sample i and z_dyn(t-k) from sample j (different scenes)

This is essentially a VICReg invariance term but across time rather than across augmentations. Wait — this is basically what SFA does! SFA minimizes ||z_dyn(t) - z_dyn(t-1)||², which IS pulling same-scene representations together across time.

The key difference between SFA and a contrastive approach: SFA only has positive pairs (minimize distance), while contrastive learning has both positive AND negative pairs (pull positives together, push negatives apart). VICReg's covariance term provides some pushing, but it decorrelates dimensions within a single sample, not across samples.

  MULTI-STEP SFA IMPLEMENTATION:
  - Maintain a z_dyn trajectory buffer (collections.deque, maxlen=110) alongside
    the replay buffer during training
  - At each step, encode the current environment frame (x_current) through the
    encoder WITH gradients and store z_dyn.detach() in the trajectory buffer
  - For the multi-step SFA loss: sfa_loss_k = MSE(z_dyn_current, z_dyn_trajectory[-k-1]) / k
  - The gradient flows through z_dyn_current back to the encoder; z_past is a
    fixed (detached) target from the buffer
  - This requires one additional encoder forward pass per step (batch_size=1),
    which is ~3% overhead over the main batch forward pass
  - The SFA loss is ADDED to the main loss (VICReg + JEPA readout), replacing
    the single-step SFA in the model's forward pass (set sfa_weight=0 in model,
    compute multi-step SFA externally)

  TEMPORAL CONTRASTIVE (NT-Xent) IMPLEMENTATION:
  - Computed inside NonParametricJEPASpatial.forward() in the SFA branch
  - Uses z_target_dyn (anchor, WITH gradients) and z_hist_dyn[:,-1] (positive,
    WITH gradients — standard SimCLR, no stop-gradient needed since VICReg
    prevents collapse)
  - NT-Xent loss:
    z_anchor = F.normalize(z_target_dyn[:, :d_t_dyn], dim=-1)  # (B, d_t_dyn)
    z_positive = F.normalize(z_hist_dyn[:, -1, :d_t_dyn], dim=-1)  # (B, d_t_dyn)
    sim_matrix = mm(z_anchor, z_positive.T) / τ  # (B, B)
    labels = arange(B)  # diagonal = positive pairs
    contrastive_loss = cross_entropy(sim_matrix, labels)
  - Uses full d_t-dimensional z_dyn vector (not per-dimension) to allow the
    model to allocate different dimensions to different identity aspects
